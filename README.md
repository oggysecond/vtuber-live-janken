# 現場猜拳

線上版：[https://oggysecond.github.io/vtuber-live-janken/](https://oggysecond.github.io/vtuber-live-janken/)

網站裡也有同一份說明：首頁 →「使用說明」／「工作人員說明」。

藝人先在手機密選猜拳，觀眾在投影幕上看不到。按下揭曉後，大螢幕倒數 3 秒再翻出超大手勢。

---

## 操作說明

### 兩個畫面

| 畫面 | 誰用 | 做什麼 |
|---|---|---|
| **控場** | 藝人或旁邊的工作人員 | 按 1／2／3 出拳、按揭曉。這個畫面只有自己看。 |
| **舞台** | 投影電腦 | 全螢幕給全場看。揭曉前不會出現手勢。 |

兩邊必須是**同一個房間代碼，而且同一組 PIN**。掃 QR 的話兩個都會自動帶上。

### 30 秒上手

1. 手機打開網站，按「建立房間」。畫面會給你一組 `房間代碼 + PIN`，例如 `H7K2-0483`。
2. 投影電腦掃控場上的 QR，或貼上舞台網址。點一下進全螢幕。
3. 等控場右上角變成「舞台有回應」。舞台一接上就會亮，掉線也會馬上暗掉。
4. 按 **1 石頭**、**2 剪刀**、**3 布**。只有控場看得到。
5. 觀眾出拳後，按金色「揭曉：倒數 3 秒」。
6. 要再玩，按「下一局」。

### 按鍵

- `1` 石頭　`2` 剪刀　`3` 布
- `Enter` 或空白鍵＝揭曉；揭曉後再按一次＝下一局
- 舞台畫面按 `F`，或點一下＝全螢幕

### 藝人注意

- 控場手機不要對準觀眾，也不要接到投影。
- 選好之後可以改，倒數開始就不能改了。
- 揭曉前舞台只會顯示「準備好了」，不會出手勢。
- 你選的拳在按下揭曉之前不會離開這支手機，網路上抓不到。

## 工作人員手冊

開場前請把這份跟藝人對一次。預設用公開網址，**兩邊都要能上網**。

### 開場前 15 分鐘

1. 投影電腦接好 HDMI。瀏覽器用 Chrome／Edge／Safari 都可以。控場和舞台**不必是同一台、也不必同一個瀏覽器**。
2. 手機打開網站 →「建立房間」。這支手機就是控場，不要再換房間。
3. 用投影電腦掃 QR。確認網址尾端的 `房號-PIN` 跟手機上顯示的完全一樣。
4. 點舞台畫面進全螢幕。右上角小綠點＝已連上。
5. 控場右上角要顯示「舞台有回應」。
6. 關著觀眾測一局：選拳 → 揭曉 → 確認大螢幕 3、2、1 後翻牌 → 下一局。
7. 測完停在「猜拳」等待畫面。手機開最高亮度、關掉自動轉橫、不要投螢幕鏡像。現場建議接充電。

### 現場節奏（建議講稿）

1. 主持：「現在跟 ○○ 猜拳，1、2、3——出拳！」
2. 藝人在控場先選好。舞台出現「準備好了」就可以讓觀眾出拳。
3. 觀眾出拳後，控場按揭曉。不要在倒數前把手機亮給台下。
4. 翻牌後看勝負。還要再來就按下一局。

### 絕對不要

- 把控場畫面投影出去。
- 把房間 QR、PIN 或舞台網址印在給觀眾的場刊上。
- 讓投影幕停在還看得到網址列的畫面——進場前就先按全螢幕。
- 用兩支手機當控場亂按。一局只留一台控場。

### 出事怎麼辦

| 狀況 | 處理 |
|---|---|
| 控場一直「等待舞台」 | 舞台重新整理。確認兩邊的 `房號-PIN` 完全相同。兩台都要有網路。 |
| 畫面出現「relay 斷線，備援通道接手中」 | 不用動，備援線會接手，節目照跑。結束後再回報。 |
| 畫面出現「兩條通道都斷了」 | 場地網路有問題。換手機熱點，或直接改「單機備用」。 |
| 畫面出現「ntfy 被限流」 | 主線仍在運作，可以繼續。不要狂刷重新整理。 |
| 按了揭曉，大螢幕沒動 | 舞台重新整理，控場再按一次揭曉。仍不行就改「單機備用」。 |
| 選錯拳、還沒揭曉 | 直接改按 1／2／3。 |
| 已經開始倒數 | 改不了。這一局走完，下一局重來。 |
| 控場被觀眾看到 | 立刻把螢幕轉開。還沒揭曉就改選。 |
| 手機休眠／畫面鎖住 | 解鎖後不要亂按。現場建議接充電。 |
| 場地網路掛了 | 改單機備用，不要硬撐公開網址。 |

### 單機備用（沒網路時）

同一台接投影的筆電，開兩個分頁：一個控場、一個舞台。桌面設成「延伸」——控場視窗留在筆電螢幕，舞台視窗拖到投影幕再全螢幕。

若現場還有這個專案資料夾：

```bash
npm install
npm run start
```

用終端機顯示的 **Network** 網址給手機，不要打 `localhost`。

沒有專案、也沒網路：改口頭猜拳。不要在台上當場裝東西。

### 分工建議

- **控場手**：站藝人側邊，負責選拳、揭曉、下一局。藝人自己按也可以。
- **舞台手**：顧投影電腦、全螢幕、音效。不要碰控場。
- **主持**：帶觀眾出拳時機。看到「準備好了」再喊出拳最順。

## 開發指令

```bash
npm install
npm run dev      # http://localhost:5173
npm run start    # 建置後 http://localhost:4173
```

### 連線架構

控場和舞台之間有三條通道，能通哪條就走哪條：

| 通道 | 角色 | 說明 |
|---|---|---|
| Cloudflare Worker relay | 主線 | WebSocket，延遲最低，並且會即時回報舞台在不在線上。 |
| ntfy.sh | 備援 | 主線不通時自動接手。免費服務有流量限制，所以心跳刻意放慢。 |
| BroadcastChannel | 同瀏覽器 | 只在同一台裝置的分頁之間有效，不跨裝置。 |

房間代碼和 PIN 不會原封不動送上網路：前端先推導成一組通道名稱才連線，
所以只知道房號的人訂閱不到。伺服器也看不到你的 PIN。

### 部署 relay

```bash
cd worker
npx wrangler deploy
```

第一次會要你登入 Cloudflare。部署完會印出網址，像
`https://vtjanken-relay.<你的子網域>.workers.dev`。
把它填進 `src/config.js` 的 `DEFAULT_RELAY`（把 `https://` 換成 `wss://`），
commit 後 GitHub Actions 會自動重新部署網站。**這一步沒做的話網站仍然可用**，
只是全部走 ntfy 備援線。

用的是 Workers 免費方案：Durable Object 走 SQLite 版本，並且開了 hibernation，
沒有訊息的時候不計費。一場活動的用量遠在免費額度內。

驗證：

```bash
curl https://vtjanken-relay.<你的子網域>.workers.dev/health
```

`src/config.js` 留空字串就會完全停用 relay，只走 ntfy 備援。
網址加 `?relay=off` 可以臨時測試備援線。
