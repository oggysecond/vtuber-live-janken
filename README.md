# 現場猜拳

線上版：[https://oggysecond.github.io/vtuber-live-janken/](https://oggysecond.github.io/vtuber-live-janken/)

網站裡也有同一份說明：首頁 →「使用說明」／「工作人員說明」。

藝人先在手機密選猜拳，觀眾在投影幕上看不到。按下揭曉後，大螢幕倒數 3 秒再翻出超大手勢。

---

## 操作說明

### 兩個畫面

| 畫面 | 誰用 | 做什麼 |
|---|---|---|
| **控場** | 藝人或旁邊的工作人員 | 按 1／2／3 出拳、按揭曉。這個畫面只有自己看。 |
| **舞台** | 投影電腦 | 全螢幕給全場看。揭曉前不會出現手勢。 |

標準配置就是這兩台：**一台控場、一台舞台**，觀眾看大螢幕。兩邊必須是**同一個房間代碼，而且同一組 PIN**，掃 QR 的話兩個都會自動帶上。

另外還有一個讓觀眾用自己手機看的連結，是備用功能，平常用不到，請見工作人員手冊的「[備用：觀眾用手機看](#備用觀眾用手機看平常用不到)」。

### 30 秒上手

1. 手機打開網站，按「建立房間」。畫面會給你一組 `房間代碼 + PIN`，例如 `H7K2-0483`。
2. 投影電腦掃控場上**紅框**的「投影電腦用」QR。點一下進全螢幕。
3. 等控場右上角變成「舞台有回應」。舞台一接上就會亮，掉線也會馬上暗掉。
4. 按 **1 石頭**、**2 剪刀**、**3 布**。只有控場看得到。
5. 觀眾出拳後，按金色「揭曉：倒數 3 秒」。
6. 要再玩，按「下一局」。

### 右上角的小燈

大螢幕上不會出現任何文字警告，只看右上角的小燈。滑鼠移到燈上會出現說明。

| 燈 | 意思 | 要做什麼 |
|---|---|---|
| 綠燈 | 一切正常 | 不用做什麼 |
| 黃燈 | 改走備用線路，還能用，可能慢一點 | 不用動，節目照跑 |
| 紅燈（會閃） | 斷線了，收不到訊號 | 看控場手機上的說明 |
| 灰燈（慢慢閃） | 連線中，或在等另一邊連上 | 等一下；太久就重新整理 |

控場手機上會用一句話說明現在怎麼了、要怎麼做。

### 按鍵

- `1` 石頭　`2` 剪刀　`3` 布
- `Enter` 或空白鍵＝揭曉；揭曉後再按一次＝下一局
- 投影電腦按 `F`，或點一下＝全螢幕（畫面上不會有提示字，記得這個操作）
- 投影電腦按 `Q`＝顯示／收起觀眾 QR（備用功能，平常用不到）

### 藝人注意

- 控場手機不要對準觀眾，也不要接到投影。
- 選好之後可以改，倒數開始就不能改了。
- 揭曉前舞台只會顯示「準備好了」，不會出手勢。
- 你選的拳在按下揭曉之前不會離開這支手機，網路上抓不到。

## 工作人員手冊

開場前請把這份跟藝人對一次。預設用公開網址，**兩邊都要能上網**。

### 開場前 15 分鐘

1. 投影電腦接好 HDMI。瀏覽器用 Chrome／Edge／Safari 都可以。控場和舞台**不必是同一台、也不必同一個瀏覽器**。
2. 手機打開網站 →「建立房間」。這支手機就是控場，不要再換房間。
3. 用投影電腦掃控場上**紅框**的「投影電腦用」QR。確認網址是 `…/#/s/房號-PIN`，而且 `房號-PIN` 跟手機上顯示的完全一樣。
   控場下面還有一個**綠框**的觀眾 QR，是備用的，**投影電腦千萬不要掃它**：畫面看起來一樣，但沒有備用線路、也沒有音效，出事時不會自動接手。掃錯的話控場會一直顯示「等待舞台」，第 5 步就會發現。
4. 點舞台畫面進全螢幕。右上角是綠燈＝已連上。
5. 控場右上角要顯示「舞台有回應」。
6. 關著觀眾測一局：選拳 → 揭曉 → 確認大螢幕 3、2、1 後翻牌 → 下一局。
7. 測完停在「猜拳」等待畫面。手機開最高亮度、關掉自動轉橫、不要投螢幕鏡像。現場建議接充電。

### 現場節奏（建議講稿）

1. 主持：「現在跟 ○○ 猜拳，1、2、3——出拳！」
2. 藝人在控場先選好。舞台出現「準備好了」就可以讓觀眾出拳。
3. 觀眾出拳後，控場按揭曉。不要在倒數前把手機亮給台下。
4. 翻牌後看勝負。還要再來就按下一局。

### 絕對不要

- 把控場畫面投影出去。
- 把**紅框**的投影電腦 QR、PIN 或舞台網址給觀眾看、印在場刊上。真的要讓觀眾用手機看，一律用**綠框**的觀眾 QR。
- 讓投影幕停在還看得到網址列的畫面——進場前就先按全螢幕。
- 用兩支手機當控場亂按。一局只留一台控場。

### 出事怎麼辦

| 狀況 | 處理 |
|---|---|
| 控場一直「等待舞台」 | 確認投影電腦掃的是**紅框**、網址是 `/#/s/` 開頭。舞台重新整理。確認兩邊的 `房號-PIN` 完全相同。兩台都要有網路。 |
| 大螢幕右上角變黃燈 | 不用動，已經自動改走備用線路，節目照跑。結束後再回報。 |
| 大螢幕右上角變紅燈 | 看控場手機上的說明。多半是網路斷了：換手機熱點，或直接改「單機備用」。 |
| 控場說「網路太擠，指令送不出去」 | 先不要連按，等 10 秒再按一次。不要狂刷重新整理。 |
| （有開觀眾連結時）觀眾說手機畫面不動 | 請他重新整理。觀眾手機只走主線，沒有備用線路；大螢幕不受影響。 |
| 按了揭曉，大螢幕沒動 | 舞台重新整理，控場再按一次揭曉。仍不行就改「單機備用」。 |
| 選錯拳、還沒揭曉 | 直接改按 1／2／3。 |
| 已經開始倒數 | 改不了。這一局走完，下一局重來。 |
| 控場被觀眾看到 | 立刻把螢幕轉開。還沒揭曉就改選。 |
| 手機休眠／畫面鎖住 | 解鎖後不要亂按。現場建議接充電。 |
| 場地網路掛了 | 改單機備用，不要硬撐公開網址。 |

### 單機備用（沒網路時）

同一台接投影的筆電，開兩個分頁：一個控場、一個舞台。桌面設成「延伸」——控場視窗留在筆電螢幕，舞台視窗拖到投影幕再全螢幕。

若現場還有這個專案資料夾：

```bash
npm install
npm run start
```

用終端機顯示的 **Network** 網址給手機，不要打 `localhost`。

沒有專案、也沒網路：改口頭猜拳。不要在台上當場裝東西。

### 備用：觀眾用手機看（平常用不到）

標準配置只有一台控場、一台舞台，觀眾看大螢幕就好。萬一需要讓觀眾用自己的手機看——例如後排看不清楚、或有第二個場地——才用這個。

控場上有兩個 QR，**一定要分清楚**：

| QR | 給誰 | 拿到的人能做什麼 |
|---|---|---|
| **紅框「投影電腦用」** | 只給投影電腦 | 等於遙控器，可以操控大螢幕 |
| **綠框「觀眾用」** | 可以公開 | 只能看、不能操作。幾百人一起看也不影響大螢幕 |

最方便的做法：在投影電腦上按 **`Q`**，大螢幕會秀出觀眾 QR 讓台下直接掃。再按一次收起來；藝人一選拳也會自動收起。控場上會顯示現在有幾個人在看。

要知道的限制：

- 觀眾手機只走主線，沒有備用線路。主線掛了觀眾手機會停在原地，但大螢幕照樣走備用線路，節目不受影響。
- 觀眾手機預設靜音，不會跟著出聲。
- 現場斷網、改用單機備用時，沒有觀眾連結可用。

### 分工建議

- **控場手**：站藝人側邊，負責選拳、揭曉、下一局。藝人自己按也可以。
- **舞台手**：顧投影電腦、全螢幕、音效。不要碰控場。
- **主持**：帶觀眾出拳時機。看到「準備好了」再喊出拳最順。


### 連線架構

控場和舞台之間有三條通道，能通哪條就走哪條：

| 通道 | 角色 | 說明 |
|---|---|---|
| Cloudflare Worker relay | 主線 | WebSocket，延遲最低，並且會即時回報舞台在不在線上。 |
| ntfy.sh | 備援 | 主線不通時自動接手。免費服務有流量限制，所以心跳刻意放慢。 |
| BroadcastChannel | 同瀏覽器 | 只在同一台裝置的分頁之間有效，不跨裝置。 |

觀眾手機走的是 relay 上**另一個獨立的房間**（`/view/<位址>`），跟上面三條完全分開：

- 觀眾網址裡只有一串位址，沒有房號也沒有 PIN。位址 = SHA-256(P) 的前 32 碼，
  P = PBKDF2(房號:PIN, 30 萬輪)。觀眾拿著位址反推不出 P，也推不出房號和 PIN；
  暴力猜約一百億種組合、每次都得跑 30 萬輪，一張顯示卡要好幾天。
- 只有出示 P 的連線（也就是控場）能在觀眾房間發訊，其他人送什麼都會被丟掉。
- 給觀眾的訊息不帶房號，倒數時也不帶手勢，揭曉那一刻才帶。
- 觀眾只走主線、沒有備用線路：主線掛了觀眾手機會停，但大螢幕照樣走備用線路。
  這是刻意的——備用線路（ntfy）的主題是公開的，拿到的人都能發訊，不能交給觀眾。
- 觀眾房間需要 HTTPS（`crypto.subtle`）。現場斷網備援用 `http://192.168.x.x` 開時沒有觀眾模式。

房間代碼和 PIN 不會原封不動送上網路：前端先推導成一組通道名稱才連線，
所以只知道房號的人訂閱不到。伺服器也看不到你的 PIN。

### 房間不會過期

房間不是被「建立」出來的東西，沒有任何伺服器上存著「房間 ABCD 存在」這筆資料。
它只是一段網址推導出來的通道名稱，所以**同一組房號＋PIN 一年後再開一樣能用**。
ntfy 上的訊息會留 12 小時（只能用 `poll=1&since=all` 明確撈，一般連線不會重播），
但那是訊息紀錄，不是房間。

因此**每一場活動都要按一次「建立房間」**。沿用舊房號的話，上一場拿過 QR 的人
仍然連得進來。

### relay 的防護

| 防護 | 數值 | 擋什麼 |
|---|---|---|
| 單一房間連線數 | 8 | 同一個房間被灌爆 |
| 單一訊息大小 | 4 KB | 超大 payload |
| 單一連線發訊頻率 | 30 則 / 10 秒 | 灌量燒掉請求配額。正常一局只送 4 則 |
| 觀眾房間人數 | 1,000 | 觀眾房間被塞爆。Worker 環境變數 `MAX_VIEWERS` 可調 |
| 觀眾房間發訊端 | 4 | 只有出示 P 的控場能發訊，觀眾送的一律丟掉 |

這些擋的是**基礎設施層面的濫用**。拿到房號＋PIN 的人送一則格式正確的假訊息
仍然可以搗亂——那只能靠保密（進場前先全螢幕，別讓網址列上投影幕）。

驗證：

```bash
node scripts/verify-relay-limits.mjs     # 控場／投影機房間的限流
node scripts/verify-viewers.mjs          # 觀眾房間：鑰匙驗證、隔離、晚到補狀態、人數上限
```

### 部署 relay

```bash
cd worker          # 一定要先進 worker/
npx wrangler deploy
```

> **務必先 `cd worker`。** 在專案根目錄執行 `wrangler deploy` 的話，wrangler 會
> 偵測到這是 Vite 專案，改成把「網站本身」部署成一個帶靜態資源的 Worker，
> 並且自動改寫 `vite.config.js`、`package.json`（連 `preview` 指令都會被換掉）
> 和 `.gitignore`。那不是 relay——它沒有 Durable Object，`/room/…` 不會運作。

目前已部署的 relay：`wss://vtjanken-relay.vtuber-live-janken.workers.dev`
（已填在 `src/config.js`）。

第一次部署會要你登入 Cloudflare。`wrangler login` 需要互動式終端機，
在 Claude Code 的 `!` 指令裡跑不起來，請開一個自己的終端機視窗執行。

換帳號重新部署時，把印出的新網址填進 `src/config.js` 的 `DEFAULT_RELAY`
（把 `https://` 換成 `wss://`），commit 後 GitHub Actions 會自動重新部署網站。
**這一步沒做的話網站仍然可用**，只是全部走 ntfy 備援線。

用的是 Workers 免費方案：Durable Object 走 SQLite 版本，並且開了 hibernation，
沒有訊息的時候不計費。一場活動的用量遠在免費額度內。

驗證：

```bash
curl https://vtjanken-relay.vtuber-live-janken.workers.dev/health
# {"ok":true,"ts":…}
```

跨裝置驗證（需要 puppeteer-core，會開兩個互相隔離的瀏覽器）：

```bash
npm run start                                   # 另開一個終端機
RELAY=wss://vtjanken-relay.vtuber-live-janken.workers.dev npm run verify:cross
npm run verify:cross                            # 不給 RELAY 則測 ntfy 備援線
```

`src/config.js` 留空字串就會完全停用 relay，只走 ntfy 備援。
網址加 `?relay=off` 可以臨時測試備援線。
